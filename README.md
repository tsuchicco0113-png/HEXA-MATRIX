# HEXA MATRIX (v0.13)

CoreMatrix (16×16 白色LED) に絵を出すための一式です。

| ファイル | 役割 |
|---|---|
| `hexa-matrix-studio.html` | STUDIO。「マークを作る」と「番組を作る」の2画面。USBで実機に映す |
| `firmware/HexaMatrixFW/` | CoreMatrix 用ファーム v0.9。microSD の番組を自分で流す。USBで届いたコマも表示する |
| `cpz/` | CardputerZero 用。常駐ハブ (`hmatrixd.py`)、本体アプリ (`hmatrix_app.py`)、描画エンジンの Python 版 (`hxengine.py`) |
| `src/` `build.py` | STUDIO の元ファイル。`python3 build.py` で1枚のHTMLに組み立てる |
| `tools/mkfont.py` | ドットフォント (BDF) をSTUDIO用の表に変換する |

## はじめる

1. Arduino IDE でボード **M5CoreMatrix** を選び、`firmware/HexaMatrixFW/HexaMatrixFW.ino` を開いて書き込む
   - M5Stack ボードマネージャ 3.3.10-a 以上、ライブラリ M5Unified / M5GFX
   - ツール → USB CDC On Boot は Enabled (既定)
   - ツール → Partition Scheme は **No OTA (2MB APP/2MB SPIFFS)** (v0.5 から Wi-Fi が入って既定の 1.2MB に入らないため。
     切り替えると本体フラッシュに保存した番組は消えます。microSD の番組はそのまま)
   - 書き込めないときは電源ボタン長押しでダウンロードモード
2. 書き込めるとハートが出る。シリアルモニタは閉じる
3. パソコンの Chrome / Edge で `hexa-matrix-studio.html` を開き、「接続」で CoreMatrix を選ぶ

## 本体だけで流す (v0.3〜、v0.7 で起動時の動きを変更)

番組 (.hxm) を microSD の `hexa` フォルダから読んで流します。カードが入っていないときは本体のフラッシュに保存します。
**v0.7 から、電源を入れても番組は流しません (消灯で待つ)。B を押すと、最後に選んでいた番組から流れます。**

| ボタン | 押す | 長押し (0.8秒) |
|---|---|---|
| A | 前の番組を流す | 番組の頭から |
| B | 番組を流す / 止める (何か出ていれば止めて消灯) | 全体の明るさ (4段、B1〜B4 と表示) |
| C | 次の番組を流す | 向きを90°回す |

- CPZ や STUDIO から絵が届いたら番組は止め、届いたものだけを出します (混ざらないように)。終わったら消灯に戻り、番組は自動では再開しません
- STUDIO / CPZ から「本体に保存」したときだけは、保存した番組をそのまま流します
- **1回だけ / 連続再生 (v0.8)**: STUDIO の番組画面の「くりかえす」(=「本体の番組」の「流し方」) が番組ごとの設定です。
  外すと、本体に保存・コマ列の書き出し・CPZに置く のどれでも「1回だけ」の番組になり、本体は最後まで流したら消灯して止まります (B でもう一度)。
  印は .hxm のコマ数の最上位ビット (v0.7 以前のファームでは「E」になります)
- 番組を切り替えると番号が一瞬出ます。読めない番組は「E」が出ます
- 番組の入れ方は2通り
  1. STUDIO の「本体の番組」→「この番組を本体に保存」(USB)
  2. 「コマ列を書き出す」で作った .hxm を、PCで microSD の `hexa` フォルダへコピー
- 番組は名前の順に並びます。`01_`、`02_` のように番号を付けると順番を決められます。名前は英数字と `_` `-` だけにしてください
- USB / Wi-Fi でコマが届いている間はそちらを出し、届かなくなって3秒で消灯に戻ります
- microSD は FAT32 でフォーマットしたものを使ってください。64GB 以上のカードは出荷時 exFAT なので、そのままでは読めません
  (Mac: ディスクユーティリティで「MS-DOS (FAT)」+「マスター・ブート・レコード」、Windows: guiformat や Rufus で FAT32)
- v0.4 から、カードが読めないときは起動時やカードを入れた時に「SD」と出ます。STUDIO の「本体の番組」にも案内が出ます
  (一度 FAT32 のカードが読めると「カードが入っている」状態を覚えるので、それ以降に読めないカードを入れると知らせます)

## Wi-Fi でつなぐ (v0.5)

microSD の `hexa` フォルダに `wifi.txt` を置いておくと、CoreMatrix が起動時に Wi-Fi につなぎます。

```
ssid=自宅のSSID
pass=パスワード
name=hexamatrix
```

- 読み込んだらパスワードを本体に覚えさせ、ファイルは `pass=*****` に書き換えます (カードを抜いても設定は残ります)
- パスワードを変えたいときは、`pass=` を新しいパスワードに書き直して入れ直します。`ssid=` を空にすると Wi-Fi を使いません (覚えた設定も消えます)
- 追加の設定 (v0.9、省略可): `sleep=on` で Wi-Fi の省電力を入れる (v0.9.2 から既定は off。v0.9〜0.9.1 は on)、`tx=11` で送信の強さ (dBm, 2〜20、既定 15)。
  Wi-Fi 中だけ表示がちらつくときは、省電力 on のまま `tx=` を下げると良くなることがあります
- `name` は省略すると `hexamatrix`。英数字と `-` だけ。CPZ からは `hexamatrix.local` で見つけます
- **合言葉 (v0.9.4、省略可)**: `key=好きな合言葉` (8文字以上推奨、32字まで)。入れると、Wi-Fi でつないできた相手は合言葉を通すまで
  何もできません (同じ Wi-Fi の他の人に番組を消されたり書き換えられたりしない)。pass と同じく `key=*****` に書き換わります。
  CPZ 側は `sudo systemctl edit hexa-matrix` → `[Service]` の下に `Environment=HMATRIX_KEY=同じ合言葉`。USB には要りません
- つながると「W」が一瞬出ます。TCP 7800 番で USB と同じパケットを受けます
- CPZ のハブは USB が無ければ Wi-Fi の CoreMatrix を探します。両方あるときは USB を使います
- wifi.txt は起動したときだけ読みます。CPZ と CoreMatrix は同じ Wi-Fi (同じルーター) につないでください
- 別の名前にしたときは CPZ 側で `sudo systemctl edit hexa-matrix` → `Environment=HMATRIX_NET=名前.local` (IPアドレスでも可)

### CPZ から流すときの仕組み (v0.6)

CPZ の「ことば」「ライブラリ → CPZから流す」は、1コマずつ送るのではなく、コマ列 (.hxm) をまとめて本体のメモリへ送り、
本体が自分の時計で流します (保存はしません)。

- Wi-Fi で1コマずつ送ると、届く間隔がばらついてカクつく / 途切れて本体の番組と混ざる、を避けるため
- 流している間は本体の番組を止めます。長さの指定が来たとき・CPZで止めたとき・本体の B を押したときに消灯へ戻ります (v0.7〜。番組は自動で再開しない)
- CPZ から流し始めると、CPZ から開いている STUDIO の「描いたらすぐ映す」「実機にも流す」は自動で外れます (交互に出ないように)。CPZ から開いた STUDIO は、この2つが最初から外れています
- 送り方は同じファイル転送 (0x10〜0x12) で、名前を `@live` (くりかえし) / `@once` (1回) にするだけ。PLAY `0xFE` で番組へ戻る
- 返事を待たずに先まで送るので、80KB 程度の番組でもすぐ始まります。ファーム v0.9.5 からは本体が PING で `"win":16` と教えてくれるので、
  **USB でも Wi-Fi でも16個先まで**送ります (STUDIO の「本体に保存」も同じ)。v0.9.4 以前のファームは Wi-Fi 8 / USB 1 のまま
- USB と Wi-Fi の両方から同時に送ると、後から来た方は `busy` で断られます (v0.9.4)。ハブは少し待ってやり直します
- Wi-Fi の省電力: v0.9.2 から既定は「切る」(受信が遅れて転送が止まることがあったため)。v0.9.6 からは消灯中だけ入れて、何か届いたらすぐ切ります (下の「向き・振る・省電力」)
- ファームが v0.5 以前なら、これまでどおり1コマずつ送ります
- STUDIO の「実機にも流す」(ブラウザからのプレビュー) も、v0.9.6 からはプレビューのコマ列をまとめて送って一時再生します
  (編集するたびに送り直し、止めると 0xFE)。256KB を超える時・送れなかった時・ファーム v0.5 以前は1コマずつ
- CPZ の転送と、CPZ から開いた STUDIO の転送 (本体に保存 / プレビュー) は、ハブが1つずつ順番に通します (v0.9.6)。
  本体から見るとどちらも同じ USB から来るので、混ざると壊れるため。ブラウザ側が途中で止まったら 8 秒で打ち切ります

## 向き・振る・省電力 (ファーム v0.9.6)

CoreMatrix の BMI270 (傾きセンサー) と電源まわりを使います。設定は本体に覚えます。CPZ アプリの「設定」か、ハブの `POST /api/device/config` で切り替えます。

| 設定 | 既定 | 内容 |
|---|---|---|
| 自動回転 `autorot` | 切 | 立てた向きに合わせて絵を回す |
| 振って次の番組 `shake` | 切 | 強く3回振ると次の番組 (C を押したのと同じ) |
| 消灯中の省電力 `psave` | 入 | 何も出していない状態が 10 秒続いたら Wi-Fi を省電力に。何か届いたらすぐ戻す |

- **自動回転は「覚える」方式です。** 画面の回転と傾きの対応は個体や置き方で決め打ちできないので、
  ・自動回転を入れた瞬間の向きを「正しい」として覚えます
  ・C 長押し (または CPZ の「向き」) で回すたびに、そのときの傾きを覚えます (言い直すと上書き)
  隣り合う2つの向き (例: 縦と横) を覚えれば4つとも当たります。1つだけでも逆さまは当たります。CPZ の設定に「覚えた向きN」と出ます
- 寝かせて置いている (画面が上を向いている) ときと、動かしている最中は回しません。0.5 秒同じ向きで止まったら回します
- 自動で回した向きは本体に保存しません (C 長押しで決めた向きだけ保存)
- 省電力: 消灯中は LED ドライバへの送り直し (0.2 秒ごと) もやめます。wifi.txt の `sleep=on` は今までどおり「いつも省電力」
- PING の返事に `"imu"` (`ok`/`none`)・`"learn"` (覚えた向きの数)・`"cfg"`・電池 `"batt"` (mV、0=電池なし)・`"lvl"` (%)・`"chg"` (充電中) が入ります

## 箱庭: キーチェーン (HEXA CUBE、ファーム v0.10)

CoreMatrix + 18350×2 ベース (`corematrix_18350x2_battery_base.scad`) のキューブをチェーンで吊るして持ち歩くと、
画面が「キャラが住んでいる箱庭」になります。**USB を抜くと箱庭、つなぐといつもの HEXA MATRIX** です。

- キャラは本体の傾きで落ちる・転がる・ぶつかる。**本体を横にしても逆さにしても、キャラは新しい「下」に立ちます**
- 叩くと跳ねる、振ると目が回る、着地でつぶれる、静かにしていると寝る (目を閉じて寝息)、動かすと起きてびっくり
- アニメは絵1枚から自動で作ります (まばたき・目線・歩く脚・伸び縮み)。組み込みのキャラは 14×10
  (エンジンは `firmware/HexaMatrixFW/hxm_char.h`、PC でテストできます)

| ボタン | 押す | 長押し |
|---|---|---|
| A | なでる (うれしい) | キャラを真ん中に戻す |
| B | おやすみ (すぐ眠る) | 明るさ |
| C | つつく (跳ねる) | 向き (**吊るした状態で、キャラが正立するまで**。傾きも覚える) |

**箱庭を抜ける**: A と C を同時に 1.5 秒長押し (USB を抜き差しするまで自動では入らない)。
CPZ の「設定 → 箱庭」の「いつも」は開発・展示用で、Wi-Fi をつないだまま・本体も眠りません (v0.10.1)。電池で持ち歩く時は「自動」。

**はじめに一度**: 吊るして C 長押しでキャラを正立させる。傾けた時にキャラが逆へ転がるなら、CPZ の「設定 → 箱庭の傾き 左右」を反対に。

**眠りと起き方**: キャラが寝てから 90 秒 (`deep`) で本体も眠ります (Wi-Fi はもともと切っています)。起きるのは
1. ボタン
2. 動かした時: BMI270 の any-motion → M5PM1 → 起床ピン (極性 `imuhi` は実機で確認中)
3. 見回り: 3 秒 (`peek`) ごとに一瞬起きて「動いたか」だけ読み、動いていなければすぐ眠り直す (2 が効かなくてもこれで起きる)

眠る前のキャラの状態は残っていて、起きると続きから始まります。

**設定** (CPZ アプリの「設定」か `POST /api/device/config`):
`hako` (auto/on/off、on は USB のままでも箱庭) / `chg` (180/650mA、**18350×2 なら 650**) / `hflip` / `imuhi` / `peek` / `deep` / `anymg` (動いたとみなす揺れ mg) / `plog` (microSD の `/hexa/power.csv` に 1 分ごとの電池の記録) / `hakoreset`

18350 は**2本の電圧をそろえてから**入れてください (並列なので、差があると入れた瞬間にセル同士で大きな電流が流れます)。

### STUDIO の「箱庭」タブ: キャラを作る (v0.11)

STUDIO の「箱庭 (キャラ)」で、**絵・性格・地形**を作って、ブラウザで動かしてから本体へ送れます。

- **絵**: 16×16 に描く (余白は自動で詰める)。目 = 上半分の「囲まれた穴」、脚 = いちばん下の列の切れ目を自動で見つけて、オレンジの丸で表示。
  「組み込み」「マークから」(マークを作るの絵)・左右反転・消す・**全体を動かす (↑↓←→、編集画面の上なら方向キーでも。はみ出した点は反対側へ)**。
  **茶色の点 = 落ちて立つ所**。「床に置く」でそこまで下げると、作図とプレビューの高さがそろいます (プレビューは描いた位置から始まって落ちる)
- **地形**: 「地形」に切り替えて描くと、キャラがぶつかる床・壁になります (緑)
- **性格**: 重さ / 跳ね返り / 止まりやすさ / 滑り出す傾き / ジャンプ力 / 最高速度 / 気まぐれ / 寝るまで / 回転の慣性
- **試す (ブラウザ)**: 画面を横にドラッグ、または ±90°・180° で傾ける。「揺らす」で吊るした揺れ。叩く・振る・なでる・つつく・寝かせる。
  スマホで開けば「スマホの傾きで動かす」で、スマホを CoreMatrix に見立てて傾けられます (iPhone は許可が出ます)。
  ブラウザの動きは本体と同じエンジン (`src/hako_engine.js` は `hxm_char.h` と 1 ステップずつ一致するのをテストしています)
- **本体で試す**: USB か CPZ 経由でつないで押すと、本体がすぐ箱庭になってそのキャラが動きます (保存しない・USB のままで OK)。
  試している間に絵や性格を変えると自動で送り直し。叩く・振る・なでる・つつく・寝かせるのボタンも本体に届きます (ファーム v0.11.1、CONFIG `hakoev=1/2/4/8/16`)。傾きは本体を実際に傾けます。「試すのをやめる」かタブを離れると、いつもの表示へ
- **本体に保存**: `/hexa/hako.hxc` に保存。次からの箱庭はこのキャラ。消すと組み込みのキャラに戻ります
- `.hxc` の書き出し・読み込み (101 バイト。友だちと交換できます)

`.hxc`: `'HXC1'` / w,h / 絵 16 行 (u16、bit x が左から) / 性格 15 バイト / 地形 16 行 / 名前 16 文字 (ASCII)。

## イベントで使う: CPZ をアクセスポイントに (v0.9.6)

会場にルーターが無いときは、CPZ が Wi-Fi のアクセスポイントになり、CoreMatrix がそこにつなぎます。

1. **家で一度だけ**: CoreMatrix を CPZ に USB でつなぎ、CPZ アプリの「設定 → APを本体に教える」で ENTER
   (または wifi.txt に `ssid2=` / `pass2=` を書く。AP の名前とパスワードは CPZ の `/etc/hexa-matrix/ap.conf`、`sh cpz/install.sh` が作ります)
2. **会場で**: CPZ アプリの「設定 → イベントAP (CPZ)」を入にする (右に名前とパスワードが出ます)
3. CoreMatrix の電源を入れる。家の Wi-Fi が 15 秒見つからないと、2つ目 (CPZ の AP) につなぎます (「W2」と一瞬出ます)
4. スマホは CPZ の AP につなぎ、設定画面の QR (`http://10.42.0.1:8090/`) から STUDIO を開く

- AP を入れている間、CPZ 自身は家の Wi-Fi から外れます (Wi-Fi が1つなので)。切ると**入れる前につながっていた Wi-Fi** に戻ります (v0.11.1。CPZ に最初から入っている別の AP 設定には切り替えません)。再起動すると自動では AP になりません
  - **家では入れない**: 入れると CoreMatrix (家の Wi-Fi のまま) も PC/スマホも CPZ に届かなくなります。会場で、CoreMatrix を2つ目の Wi-Fi でつなぐ時だけ
  - 戻れなくなったら CPZ のターミナルで `sudo nmcli con up "家のWi-Fiの名前"`
- NetworkManager (`nmcli`) が必要です。2.4GHz・WPA2 固定 (CoreMatrix は 5GHz を使えません)
- 2つ目の Wi-Fi を Wi-Fi 経由で書き換えることはできません (USB か microSD だけ)
- 合言葉 (`key=`) を入れておくと、会場で他の人のスマホが AP につないでも本体は操作できません

## CardputerZero で使う

CPZ に CoreMatrix をUSBでつなぐと、CPZ が「頭脳」になります。

```
CoreMatrix ──USB── CardputerZero ──Wi-Fi── スマホ / PC のブラウザ (STUDIO)
                    └ 本体アプリ「HEXA MATRIX」(キーボードで操作)
```

1. CPZ で `git clone https://github.com/tsuchicco0113-png/HEXA-MATRIX ~/hexa-matrix && cd ~/hexa-matrix && sh cpz/install.sh`
2. 案内どおり `sudo reboot`
3. CPZ 左の USB-SW を **Host 側 (右/下)** にして、CoreMatrix を USB-A か USB-C1 につなぐ (Wi-Fi で使うなら上の wifi.txt)
4. スマホ/PCのブラウザで `http://<CPZのIP>:8090/` を開く → STUDIO が開き、自動で CPZ 経由に接続します
   (WebSerial が要らないので、スマホや Safari でも送れます)

- 常駐ハブ `hexa-matrix.service` (ポート 8090) が USB を一手に持ちます。STUDIO も本体アプリもここを通ります
- STUDIO の「保存と書き出し」に **CPZに置く** が出ます。番組を CPZ のライブラリ (`~/.local/share/hexa-matrix/library/`) に置き、
  CPZ が同じエンジン (Python版) でコマ列を作ります (STUDIO と1バイト違わないことを確認済み)
- ホーム画面の「HEXA MATRIX」アプリ (方向は F/X/Z/C、ことば画面では fn+F/X/Z/C)

| 画面 | できること |
|---|---|
| 1 ことば | 打った文字をその場で流す。動き・入り方・はやさ・明るさ・字 (16/8ドット、太字)・長さ (ずっと/1回だけ/10秒〜10分) を選べる (英数字と記号) |
| 2 ライブラリ | CPZに置いた番組を CPZ から流す (くりかえし / 1回)、本体(SD)へ送る、消す |
| 3 本体 | CoreMatrix の中の番組を選んで流す、止める、消す |
| 4 設定 | CoreMatrix の明るさ、向き、自動回転、振って次の番組、消灯中の省電力、箱庭、充電の速さ、箱庭の傾き左右、イベントAP、APを本体に教える、電池、スマホから開くQR |

- ブラウザから送り始めると、CPZ からの再生は止まります (後から操作した方が優先)
- 困ったとき: `journalctl -u hexa-matrix -n 30` / アプリのログ `~/.local/share/hexa-matrix/app.log`

## 通信の形

`A5 5A <type> <len> <payload> <crc8>` (crc8 は type, len, payload の CRC-8 / 多項式 0x07)

| type | len | 内容 |
|---|---|---|
| 0x01 FRAME | 32 | 1コマ。上の行から、各行は左8点→右8点、MSBが左、1=点灯 |
| 0x02 BRIGHT | 1 | USBで流すときの明るさ 0〜255 (16段階に丸める) |
| 0x03 PING | 0 | 状態を1行のJSONで返す |
| 0x04 ROTATE | 1 | 向き 0〜3 |
| 0x05 BENCH | 0 | 描画速度を測って返す |
| 0x06 AUTH | n | 合言葉 (v0.9.4、Wi-Fi の時) |
| 0x07 CONFIG | n | 設定 `autorot=1;shake=0;psave=1` / `rotreset=1` / `rotlearn=1`。`ssid2=…` `pass2=…` は1つずつ・USBだけ (v0.9.6) |
| 0x10 FILE_BEGIN | 4+n | u32 大きさ + ファイル名 |
| 0x11 FILE_DATA | 2+n | u16 通し番号 + 中身 (200バイトまで)。1つごとに `{"ok":true,"ack":番号}` |
| 0x12 FILE_END | 4 | u32 CRC-32。合えば `{"ok":true,"saved":名前,"idx":番号}`、一時再生なら `{"ok":true,"clip":コマ数,"loop":…}`、箱庭のキャラ (`@char` = 試す / `*.hxc` = `hako.hxc` に保存、v0.11) なら `{"ok":true,"char":名前,"try":true}` / `{"ok":true,"saved":"hako.hxc","char":名前}` (PING の `"clip"` は true/false なので、数かどうかで見分ける) |
| 0x13 LIST | 0 | 番組一覧 `{"ok":true,"list":true,"store","sd","free"(KB),"cur","paused","files":[{"n","s"}]}` |
| 0x14 DELETE | n | ファイル名 |
| 0x15 PLAY | 1 | 番組の番号 (0から)。0xFF で一時停止、0xFE で一時再生をやめて番組へ (v0.6) |

本体からの返事は1行ずつのJSONです。v0.4 から PING と LIST の返事に `"sd"` (`ok` / `unreadable` = カードが読めない / `none`) が、v0.5 から PING に `"wifi"` (`ok` / `connecting` / `off`)・`"ip"`・`"name"` が入ります。
Wi-Fi (TCP 7800) でも同じパケット・同じ返事です。

## マークを作る: コマアニメとトゥイーン

- グリッドの下の帯がコマの並び。`＋コマ` `⧉ 複製` `削除` `◀ ▶` (並べ替え)、`オニオン` で1つ前のコマを薄く表示。`[` `]` キーでコマ移動
- `▶ 再生` で大きいグリッドに動きを流す (1〜30コマ/秒、「くりかえす」を外すと1回だけ)。「描いたらすぐ映す」がオンなら実機にも流れる。再生中にグリッドを押すと止まってそのコマを描ける
- **トゥイーン**: 今のコマの絵から、はじめ→おわり の間で 横/縦の位置・大きさ%・点の残り% を補間してコマを自動で作る
  - 補間は 一定 / だんだん速く / だんだん遅く / ゆっくり→速く→ゆっくり / 弾む、往復も可
  - ひな形: 上下にゆれる・左から入る・右へ抜ける・上から落ちて弾む・下からポップ・ふわっと出る/消える・まん中から広がる・ドキドキ
  - 「点の残り」は LED が点くか消えるかだけなので、4×4 の網目で点を間引いて表す
  - 入れ方は「今のコマの後ろに足す」か「今のコマと入れ替える」。コマは64まで。戻す/進むはコマの追加・削除・トゥイーンも含めて効く
- `番組に入れる` で、番組の最後にコマアニメのシーンとして足す (コマが1つならマークのシーン)
- マーク置き場に保存するとコマも一緒に残る (`frames` と `fps`)。番組の「コマアニメ」でそれを選ぶとコマが丸ごと入る
- 出力の C配列 / JSON もコマが複数なら全コマ分

## 番組を作る

シーンを上から順に流します。シーンは「素材 × 入り方 × 見せ方 × 出方」の組み合わせです。

| 項目 | 選べるもの |
|---|---|
| 素材 | 文字 (16ドット1行 / 8ドット2行まで、太字可) / マーク / コマアニメ |
| 入り方・出方 | なし、← → ↑ ↓ に流れる、ワイプ、1字ずつ、粒で、落ちて、フェード、ズーム |
| 見せ方 (文字・マーク) | 止める (長い文はページ送り)、← → 横流し、↑ 縦送り、波打ち、往復、点滅、反転点滅、ゆっくり明暗 |
| 見せ方 (コマアニメ) | くりかえし、行って戻る |

- 横流し・縦送り・波打ちは、端から入って端へ抜けるので入り方・出方は使いません
- 明るさはシーンごと。フェードとゆっくり明暗は本体の明るさ (16段階) で作ります
- 番組はブラウザに自動保存。「番組を書き出す」で JSON、「コマ列を書き出す」で本体単体再生用の `.hxm`

### ヘッダーとフッター

番組一覧のいちばん上と下にある枠です。毎周の頭と終わりに挟みます。

- 左のチェックで使う・使わないを切り替え、右で出す間隔 (毎回 / 2・3・5・10周に1回) を選びます
- 中身はふつうのシーンと同じで、文字・マーク・コマアニメのどれでも作れます
- 間隔がちがうときは、そろうまで周を重ねた形で再生・保存します (例: 2周に1回と3周に1回なら6周ぶん)。本体に保存してもこの順番どおりに流れます

### フォント

- 16ドット: 東雲フォント (Public Domain)
- 8ドット: 美咲ゴシック (商用含め自由に利用・再配布可)
- JIS第1・第2水準の漢字、ひらがな、カタカナ、半角カナ、英数記号。無い字は「?」になります

### コマ列 (.hxm)

`'HXM1'` / u32 コマ数 / コマごとに u16 表示時間ms・u8 明るさ(0〜255)・32バイトの絵 (すべてリトルエンディアン)

### v0.9.2 — Wi-Fi 転送の止まりの修正と切り分け
- ファーム: Wi-Fi の受け取りで、パケットの途中で 0.3 秒間が空くと捨てていたのをやめる (TCP は遅れても必ず届くため)。省電力は既定で off に戻す。PING の返事に `net` (rssi / sleep / 受け取ったバイト・パケット数 / BEGIN・DATA・END の数 / 捨てた数) を出す
- ハブ: Wi-Fi の返事待ちを 8 秒に。失敗したら どの段階 (開始 / 中身 k/n / 終わり) で止まったかと、本体の `net` をログに出す

### v0.9.3 (ハブ) — Wi-Fi では1コマずつ送りに落とさない
- ことば/ライブラリ再生は、いつもコマ列を先に本体のメモリへ全部送ってから本体の時計で流す。Wi-Fi で送れない時は3回までやり直す (2回目からは1つずつ確かめながら)。それでも駄目ならエラーを出して、点滅する1コマずつ送りにはしない (USB の時だけ従来どおり落とす)

### ファーム v0.9.3 — Wi-Fi の転送失敗・点滅の本当の原因
- loop() で時刻 `now` を Wi-Fi の受け取り (netTick) より前に取っていたため、Wi-Fi で受けた直後に `now - 受けた時刻` が負 (符号なしで巨大) になり、受け取りを時間切れとして捨てる / 1コマ送りを「止んだ」として消灯する、をしていた。USB は先に読むので起きなかった。netTick の後で now を取り直し、比較を符号付きに

## 旋回の自動調整とジャイロなしの時 (ファーム v0.14.0、ハブ v0.13.8、CPZ アプリ v0.13.8)
### 自動調整 (CONFIG `tcal=1`)
歩く → 設定 → 旋回の自動調整 → ENTER。床に置いて約2分。片道 250/350/450ms で旋回スキャンを 3 回行い、
「左右どちらにも回れて、1秒あたり一番回る片道」を選んで `thalf` と当たりの角度 `tgood` を本体に保存する。覚えた左右の距離 (`toff`) は消して覚え直す。
- サーボ・クランクを替えた時、別の個体を組んだ時に 1 回やればよい
- 当たりの角度 = 選んだ片道で回れた量 (左右の小さい方) × 0.08 (8〜30°)。実機 350ms (+200 / −161) で 13°
- どの片道でも片方に 20° 回れなければ「回れる片道なし」で、設定は変えない (クランクの 180° ずれなどを疑う)
- 起動時に勝手には走らせない (机の上で急に動くと落ちる)。歩く指令が来たら途中でやめる
- `tcal=0` で中止、`tcalclr=1` で既定 (350ms / 15°) に戻す。PING の `walk.cal` = `{st: 0なし/1中/2済/3中止/4ジャイロなし/5回れない, i, saved, sc[3](°/秒)}`、`walk.tgood`

### ジャイロなしの時の縮退
ジャイロが読めない (起動時に IMU なし、または読めない 0.5 秒・値が固まって 1.5 秒) と `walk.gyro=0` になり:
- 前後に歩く・刻む・加減速・顔・プログラムの前後ステップは**そのまま動く**
- その場旋回・まっすぐ補正・スキャン・自動調整は**止める** (旋回の指令は断って止まる。数は `walk.tnoimu`)
- 値がまた変わり出したら自動で戻る (`walk.gdead` = 死んだ回数)

時間だけで回す開ループ旋回は入れていない。FS90R は位置が読めないので、往復を始めた時のクランクの位相が分からず、
同じ時間往復させても左へ回るか右へ回るか回らないかが決まらない (スキャン結果のとおり位相で +200° 〜 −161° まで変わる)。
「逆へ回るかもしれない旋回」より「回らない」方が壊れ方として優しいので、止める。

### 向きの割り切り (仕様)
- CoreMatrix は地磁気センサーを持たない (BMI270 = 加速度 + ジャイロ)。**絶対方位 (北) は分からない**。向きはジャイロを積分した相対角だけ
- 相対角はゆっくりずれる。止まっている時の小さな回転 (0.6°/秒 以下) は数えないので、長く置くほどずれは小さく抑えるが 0 にはならない
- まっすぐ補正の基準は「歩き出してから 0.6 秒後の向き」で、歩き直す・向きを変えるたびに取り直す。長い時間の向きは保たない
- 8 秒で戻せなければ、いまの向きを新しい基準にしてあきらめる。何度も止まって回り直すより、少し曲がっても歩き続けるのを選ぶ
- 「旋回で何度回る」はジャイロの相対角なので短い時間なら使えるが、何周もの累積や部屋の中の位置合わせには使えない

## その場旋回とまっすぐ補正 (ファーム v0.13.6、ハブ v0.13.5、CPZ アプリ v0.13.3)

旋回スキャンで、FS90R でも往復の位相によって左右どちらにも大きく回れることが分かった (実機: 8 位相で −143°〜+76° / 2.5 秒)。
FS90R は位置が読めないので、本体はジャイロで「狙った向きに回っているか」を見て位相を探します (v0.13.7):
探す間は 1 往復ごとに見て外れなら位相を前へ送る → 当たればつかんで 2 往復ごとに見る → 回る量が減ってきたら片道の 1/4 だけ直す (直す向きは覚える) → 2 回続けて外れたら見失った所の近くを前後に探す。

- **操作画面の ←→** (押してる間) でその場で左 / 右に回る。プログラムの動きにも **左旋回 / 右旋回** (速さの ←→ を端まで回す) が使えます。最初の E / Q は 3 秒の右 / 左旋回
- **まっすぐ補正** (設定): 歩き始めて 0.6 秒後の向きを覚え、**補正を始めるずれ** (既定 10°) を超えたら止まって旋回で戻し、また歩きます。
  v0.13.8: ずれは 0.5 秒の平均で見る (一歩ごとの揺れで動き出さない)、戻す途中で逆向きに切り替えない、8 秒で戻せなければ今の向きを基準にしてあきらめる
- v0.13.9: 左右を続けて切り替える時は前に回れた所へ直接行く。**左右の当たりの距離** を覚えて本体に保存し、探している最中に逆の当たりにいると分かったら一気に送る (左回りの立ち上がりが速くなる)。歩行ベースを組み直したら設定で消す
- **旋回の片道** (既定 350 ms。v0.13.6 は 250)。変えても調整のやり直しは要らない (探し方は毎回ジャイロで決める)。旋回スキャンは良い片道を選ぶための目安 は往復の片道の時間。回りにくい時は旋回スキャンの結果を見て合わせます
- 探す間は少し前に進むことがあります (位相を送るため)

## 旋回スキャン (試験、ファーム v0.13.5、ハブ v0.13.4、CPZ アプリ v0.13.2)

上流 (stackchan-strider) は、首のサーボを 90° の幅で往復させるとその場で回り、回る向きは往復の中心 (脚の位相) で決まることを確かめています。
FS90R は位置が読めないので、本体が自分で試します。「歩く」の設定 (TAB) の **旋回スキャン** で ENTER を押すと、
全力 (速さの上限は無視) で前後に **片道** ms ずつ 5 往復 → 止まってジャイロで回った角度を測る → 片道の半分だけ前へ送って位相をずらす、を 8 回 (約 30 秒) くり返し、
**結果 1〜4 / 5〜8** に回った角度 (°、+ が左回り) を出します。片道は ←→ で 100〜800 ms (既定 250)。歩く操作をするとやめます。
大きく + と − に回る位相があれば、その場旋回とまっすぐ補正に使えます。

## 刻んで歩く (ファーム v0.13.4、ハブ v0.13.3、CPZ アプリ v0.13.1)

続けてサーボを回すと時計回りに曲がる個体でも、ボタン連打のように「動く → 休む」をくり返すとまっすぐ進むことがあります。
「歩く」の設定 (TAB) の **歩き方** を「刻む」にすると、本体が **動く時間** (`won`、既定 0.5 秒) と **休む時間** (`woff`、既定 0.3 秒) をくり返します。
↑↓・プログラムのどちらにも効きます。加速・減速のゆっくり (wacc / wdec) も効くので、休む時間が短いと止まりきらずに次へ進みます。

## 歩行の加速・減速 (ファーム v0.13.3、ハブ v0.13.2、CPZ アプリ v0.12.2)

CoreMatrix がサーボより前に載るので重心が前寄りで、急に止まると慣性で前に倒れます。v0.13.3 から速さを急に変えず、ゆっくり寄せます。
CPZ の「5 歩く」の **止まる時のゆっくり** (`wdec`、既定 0.9 秒で 100% → 0) と **動き出しのゆっくり** (`wacc`、既定 0.3 秒で 0 → 100%) で調整できます。
前後を急に切り替えた時も、いったん減速してから逆へ加速します。倒れる時は wdec を長く、wmax (速さの上限) を下げてください。

## 緑の電源 LED (ファーム v0.13.2、ハブ v0.13.1、CPZ アプリ v0.12.1)

CoreMatrix の SD カード横の緑 LED は M5PM1 の LED_EN で点く電源 LED です(赤は充電 IC の CHG_STAT で、充電中だけ点きます)。
電源 OFF は PWR ボタンの**ダブルクリック**で。緑も消えます。長押しは BOOT (書き込みモード) なので、画面は消えても緑が点滅したままになります。
動作中に緑を消したい時は、CPZ の設定「緑の電源LED」か `CONFIG pled=0` で消せます(M5Unified が起動のたびに点けるので、ファームが起動後に毎回設定どおりに戻します)。

## 歩行モード: Stackchan Strider (ファーム v0.12、CPZ アプリ v0.11、ハブ v0.12)

[Stackchan Strider](https://github.com/Yeq6X/stackchan-strider) (Yeq6X さん、MIT) の4脚ベースを、
CoreMatrix + 18350×2 ベース + 連続回転サーボ **FEETECH FS90R** で歩かせます (改造部品は `hardware/strider/` の horn_hub / cm_yoke / cm_cradle)。

### つなぎ方

| FS90R の線 | つなぐ先 |
|---|---|
| 赤 (+) | Grove (PORT.A) の **赤 = 5V** (ファームが M5IOE1 の IO5 で 5V を入れる。最大 470mA) |
| 茶 (−) | Grove の **黒 = GND** |
| 橙 (信号) | M5-Bus の GPIO (既定なし。CPZ の「歩く」→ サーボの GPIO で選ぶ。例 G23) |

- **Grove の黄・白 (G0/G1) にはつながない**。本体の中の I2C (IMU・LED・電源) と同じ線です。ファームも 0/1/12/13 は選べません
- サーボの電源に 470µF くらいのコンデンサを並列に入れると、動き出しで電圧が落ちにくくなります

### 使い方 (CPZ)

1. ホームの **5 歩く** (またはキー 5)
2. 「歩くロボット」を入 → 電池でも箱庭に入らず Wi-Fi のまま、Grove の 5V が入る (本体に覚える)
3. 「サーボの GPIO」を選ぶ。「中立の補正」を ←→ で変えると2秒だけ中立を出すので、サーボが止まる値に合わせる
   (FS90R は底のトリマーでも合わせられます)
4. CPZ アプリ v0.13.0 から「歩く」は 3 つの画面に分かれます
   - **操作画面** (最初に開く): 十字 (↑ 前進 / ↓ 後退 / 真ん中 = 止)、いまの速さのバー、ジャイロの向き、プログラムのキー一覧だけを大きく表示。
     **↑↓** 歩く (既定は押してる間だけ。設定で「押したら続く」にも) / **SPACE** 止まる / **1〜7** 顔 / **英字キー** そのプログラムを実行 / **TAB** 設定 / **P** プログラム編集
   - **設定** (TAB): 速さ・操作・顔・サーボの GPIO・中立の補正・前後・速さの上限・止まる時/動き出しのゆっくり など。ESC で操作画面へ
   - **プログラム** (P): 動き [速さ % (+前 / −後), 秒] の並び + くりかえし + キーを作って保存 (CPZ の `~/.config/hexa-matrix/app.json`)。
     一覧: ↑↓ 選ぶ / ENTER 編集 / R 試す / N 新規 / BS 2 回で消す。編集: 名前は文字を打つ、動きの行は ←→ で変更・ENTER で速さ⇔時間・`+` 足す・`-` 消す、「▶ 試す」
   - 最初から入っているプログラム: **E 右に回る(仮)** 前1.0秒+後0.2秒 ×3 / **Q 左に回る(仮)** 後1.0秒+前0.2秒 ×3 / **W ちょっと前** 3秒 / **S ちょっと後ろ** 3秒。
     旋回の秒数は実機に合わせて直してください (キーは英字。F/X/Z/C は方向、P は編集なので使えません)

- 安全: 本体は WALK が 0.5 秒来ないと止まる。ハブは CPZ アプリからの頼み直しが 1.5 秒来ないと止める。アプリを閉じても止まる。
  本体のボタンを押しても止まる
- 速さの上限は既定 60% (原作のシミュレーションで 100% は跳ねて進みが落ちるため)
- **箱庭のキャラで歩く (ファーム v0.13)**: 顔 7 (CPZ のキー 7) = 箱庭 (HEXA CUBE) と同じキャラ・同じエンジン。
  「おまかせの顔」を「箱庭のキャラ」にすると、いつもキャラで出す (`wchar=1`、本体に覚える)。
  歩いている間はキャラもその場で脚を動かして歩く (前進は右向き、後退は左向き)。傾き・揺れはそのまま効き、
  段差でガタッとすると跳ねる、持ち上げて振る・その場で速く回ると目が回る、止まって静かにしていると寝る、歩き出すと起きてびっくり。
  止まっている時は本体の A でなでる・C でつつく (箱庭と同じ)。キャラは STUDIO の「箱庭」で作って本体に保存したもの (無ければ組み込み)
- 「向き」はジャイロで数えた床の上の回転 (度)。その場で回る歩かせ方を探す・角度で止める、の下準備です (`yawzero=1` で 0)

### パケット・API

- WALK (0x08) len=3: int8 速さ -100〜100% / u8 有効時間 (0.1 秒単位、0 は 0.5 秒) / u8 顔 (0=おまかせ、1〜5、0xFF=そのまま)。返事なし
- CONFIG: `walker=0/1` `servo=GPIO (-1 で使わない)` `strim=µs` `sinv=0/1` `wmax=%` `yawzero=1` `strimtest=1` `wchar=0/1` (v0.13)
- PING: `"walk":{"walker","pin","trim","inv","max","spd","us","show","face","wchar","cst","cmds","tmo","yaw","wz"}` (cst = キャラの状態、-1 はキャラを出していない)
- ハブ: `POST /api/walk {"speed":40,"face":2}` (1.5 秒ごとに頼み直す) / `POST /api/walk/stop`
- PC でのテスト: `g++ -std=c++17 tests/walk_test.cpp && ./a.out`、`python3 tests/fakecm.py --fw 0.12.0`
